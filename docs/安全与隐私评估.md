# 投屏Window · 安全与隐私评估报告

> 评估对象：投屏Window 桌面版 v1.1.1（手机镜像接收端，Miracast / Wi-Fi Display）
> 评估范围：投屏内容与投屏会话信息（开始/结束时间）在**无线链路、系统、本机其他程序、本程序自身**四个层面被第三方获取的可能性
> 评估方式：源码逐行核查 + 本机 Windows SDK 投影元数据核实 + 随程序交付的自检用例（`--vault-only`）
> 说明：凡是**未能实测**的结论都在文中显式标注「待实测」，不当作已证事实。

---

## 一、一句话结论

**你的投屏内容在无线链路上被"隔空监听"的可能性很低**（Miracast 走 Wi-Fi Direct 点对点链路，链路层有加密，被动抓包拿到的是密文）；
**真正的风险不在空口，而在三个地方**：① 谁能连上这台电脑（配对授权）；② 这台电脑上有权截屏/录屏的其他程序；③ 你自己保存下来的截图与录像文件。
本次加固把 ②③ 做掉了，并把 ① 收紧；剩下的风险属于「物理视线、管理员权限、系统自带功能」，软件无法根除，只能按第七节的清单关闭。

## 二、威胁模型（你要防的是谁）

| 角色 | 能力 | 本次是否覆盖 |
| --- | --- | --- |
| 同 Wi-Fi 下的邻居 / 路人 | 能搜到设备名、能尝试发起投屏连接 | ✅ 已收紧（配对确认 / 可选 PIN / 禁止抢占 / 关闭反向输入） |
| 拿到你电脑的人（未登录你的 Windows 账户） | 能看到 `%LocalAppData%`、能拷走库文件 | ✅ 已覆盖（内容用密码加密，拷走也解不开） |
| 拿到你电脑的人（你的 Windows 会话已登录） | 能打开本程序、能运行任意程序 | ⚠️ 部分覆盖（库要密码；但界面可见，需靠 Ctrl+Alt+L 上锁） |
| 电脑上运行的其他程序（会议软件、远程协助、录屏、系统截图） | 能截取屏幕 | ✅ 已覆盖（反截屏保护，实测见第八节） |
| 系统自带功能（Game Bar 后台录制、回忆/Recall） | 能周期性录屏/截屏 | ⚠️ 已提供体检与一键关闭，需你确认 |
| 管理员 / 内核级攻击者、硬件采集卡、摄像头 | 无所不能 | ❌ 无法防御（见第六节） |

## 三、无线链路：会不会被别人"监听"到投屏内容

| 项 | 结论 | 依据 |
| --- | --- | --- |
| 手机 → 电脑的画面传输 | 走 **Wi-Fi Direct 点对点链路**，链路层加密（WPA2/WPA3 级别的会话密钥，密钥在配对阶段协商） | Miracast 规范要求链路保护；Windows 平台的接收端在解密失败时会返回 `MiracastReceiverDisconnectReason.MediaDecryptionError`（本机 SDK 元数据核实存在该枚举），说明媒体确实是加解密后传输的 |
| 用普通网卡抓包能否还原画面 | **不能**（拿到的是密文）。要还原需要拿到会话密钥，而密钥不经过可嗅听的明文通道 | 同上；**待实测**：本机没有专业抓包环境，未做空口验证 |
| 是否走路由器（局域网） | 本程序使用平台默认接收端，链路为 Wi-Fi Direct，**不经过路由器**。若你手动启用了 Windows 的「Miracast over Infrastructure / 投影到此电脑」并走局域网，则流量会经过 AP 与路由器，此时**局域网内嗅探与 ARP 欺骗才是现实威胁** | 代码：`src/CastReceiver.Core/Miracast/MiracastService.cs` 仅使用 `MiracastReceiverSession`，未启用任何局域网投屏通道 |
| 谁能发现这台电脑 | 开启接收端后，附近设备能在投屏列表里看到设备名（默认 `PC`，中性名，不暴露身份）；**能看到名字 ≠ 能看到内容** | `CastSettings.DeviceName` 默认值 `PC` |
| 连接时有没有"中间人" | Miracast 的配对由平台完成（WPS/NAN 流程），本程序不参与密钥协商，因此也无法被本程序削弱；风险点在于**授权策略过松**（见下节） | 代码仅设置 `AuthorizationMethod` 与 `RequireAuthorizationFromKnownTransmitters` |

**结论**：空口窃听不是现实威胁；**"谁能连上"才是**。

## 四、配对与授权：谁能把画面投到你的电脑上

| 风险 | 加固前 | 加固后 |
| --- | --- | --- |
| 未经确认就被连接 | 默认已要求本机确认（`ConfirmConnection`） | 保持，并新增**可选「要求 PIN」**：配对时本机显示 PIN，需要在手机上输入（部分手机不支持会自动退回本机确认） |
| 别人的设备**抢占**你正在进行的投屏 | `AllowConnectionTakeover = true`（任何人可顶掉你的投屏） | **默认关闭**（设置 → 安全 可开），别人不能顶掉你的画面 |
| 发送端**反向控制本机键鼠** | 未处理（协议允许发送端请求键盘/手柄输入转发） | **连接时显式关闭**键盘与手柄输入转发；若对方请求过，会写一条告警日志 |
| 系统长期保存"上次连接过的设备" | 每次启动清空 | 改为可配置（设置 → 安全 → 启动时清空设备历史，默认保留以便少一次配对） |
| 连接事件留痕 | 日志明文记录设备名、MAC、PIN、连接/断开时间 | **隐私日志模式（默认开）**：会话事件只进界面，不写日志文件；设备名/MAC/PIN 不再进日志 |

代码位置：`src/CastReceiver.Core/Miracast/MiracastService.cs`（`DisableTransmitterInput`、`AllowConnectionTakeover`、`PairingMode`）、`src/CastReceiver.Core/Infrastructure/AppLog.cs`（`PrivacyMode` / `Event`）。

**待实测**：`MiracastTransmitter.AuthorizationStatus` 是否可写（若能写，可实现"只允许已绑定设备投屏"的更严格模式）；设备名+MAC 指纹在多次连接/重启后的稳定性（影响"设备归属"的自动识别准确率）。

## 五、本机侧：别人在这台电脑上还能怎么看到你的投屏

| 渠道 | 加固前 | 加固后 |
| --- | --- | --- |
| 会议共享 / 远程协助 / 录屏软件截取镜像窗口 | 可完整截取 | **反截屏保护（默认开）**：对这些程序显示为黑屏 |
| 系统截图工具（Win+Shift+S）、PrintScreen | 可截取 | 同上被挡（黑屏） |
| Xbox Game Bar 后台录制 | 可能在你不知情时录屏 | 设置 → 安全 → **隐私体检**可一键关闭（改的是当前用户设置，随时可改回） |
| Windows「回忆 / Recall」（Copilot+ PC 会周期性截屏） | 不受控 | 体检会检测并给出关闭指引（不代为修改系统隐私设置） |
| 窗口标题、托盘气泡、通知 | 显示手机名称（"XXX 正在投屏到本机"） | 默认**只显示"已连接/已断开"**，可在设置里改回显示设备名 |
| 托盘/任务栏残留 | 显示设备名 | 同上 |

**注意**：反截屏保护**对物理视线无效** —— 站在你身后的人照样看得见屏幕。这是软件无法解决的。

## 六、应用自身：以前有哪些明文与痕迹（本次重点）

| 旧行为 | 位置（加固前） | 风险 | 现在 |
| --- | --- | --- | --- |
| 截图存成**明文 PNG**，文件名带时间戳 | `CaptureService.SaveScreenshot` | 任何人打开文件夹即可看到，且文件名暴露时间 | 改为**加密写入库**，文件名是随机 GUID |
| 录像把**明文 JPEG 帧**写进 `%TEMP%\CastReceiverFrames_*`，再合成**明文 MP4** | `Mp4Recorder` | 临时目录明文、崩溃后残留、最终文件任何人可播 | 帧在内存中编码后**立即加密**写库；不再产生任何明文中间文件；旧残留可在设置里一键清理 |
| 日志记录 `手机已连接：{设备名} ({MAC}) PIN={PIN}` | `MiracastService` | 投屏设备、时间、PIN 全部落盘 | 隐私日志模式默认开；并提供「清除日志文件」 |

| 抓屏可能把压在上面的**别的窗口**录进去 | `GetStageScreenRect` + `CopyFromScreen` | 录到别人的内容 | 抓屏前校验前台窗口；若走窗口取帧则根本不会拍到别的窗口 |

## 七、加密库：文件被拷走会怎样

**设计**（详见 `src/CastReceiver.Core/Security/`）：

```
账号：RSA-2048 密钥对
  公钥 → 明文保存（不是秘密）→ 录制/截图只需要公钥 ⇒ 启动、投屏、录制全程免密
  私钥 → 用密码派生的 KEK 加密保存
         KEK = PBKDF2-HMAC-SHA256(密码, 随机盐, 600,000 次)
每条内容：一次性内容密钥 CK（32 字节随机）
  CK 用公钥包裹（RSA-OAEP-SHA256）→ 存进文件头
  每一帧：AES-256-GCM 独立加密，AAD 绑定「条目 ID + 块序号 + 块类型」
```

| 攻击者拿到的东西 | 能否看到内容 |
| --- | --- |
| 整个 `%LocalAppData%\CastReceiver\vault` 目录（拷到别的电脑） | ❌ 不能：私钥被密码加密，内容被 AES-GCM 加密 |
| 目录 + `accounts.json`（含公钥、盐、被包裹的私钥） | ❌ 不能：只能对密码做离线爆破（600k 次 PBKDF2/猜测 + 强密码策略） |
| 篡改文件（改一字节、换块、拼接别的条目） | ❌ 该帧校验失败并拒绝输出，不会显示错误画面 |
| 录制中强制断电/杀进程 | ✅ 已录部分可播，标记为「未完成」；不会损坏整库 |
| 删除文件后做数据恢复 | ⚠️ SSD 上无法保证擦除干净（见下节） |

**已核实的自检结论**（`CastReceiver.SelfTest.exe --vault-only`，9 项全部通过）：

| 用例 | 结果 |
| --- | --- |
| 密码是唯一钥匙（错误密码/他人私钥/弱密码） | 通过：错误密码拒绝、他人私钥拒绝、弱密码拦截 5/5 |
| 写入→读出（帧字节一致、缩略图、元数据） | 通过 |
| 篡改 1 字节 → 该帧拒绝输出，其它帧不受影响 | 通过 |
| 崩溃/断电恢复（无结束标记、物理截断） | 通过 |
| 防移植（把别的条目里的帧块搬过来） | 通过：解密失败 |
| 改名只重写加密头（内容不变、文件长度不变） | 通过 |
| 磁盘无明文（标题/时间/设备指纹不出现；文件头不是 PNG/JPEG/MP4） | 通过 |
| 文件时间归一化（不泄露"什么时候录的"） | 通过：全部为 2000-01-01 |
| 性能（100 帧 × 256KB） | 通过：约 0.7 ms/帧、346 MB/s，远低于 10fps 录制的 100ms 预算 |

## 八、反截屏实测与降级

窗口加 `SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE)` 后，**所有**捕获者（包括本程序自己用 GDI 从屏幕取像素）都会拿到黑屏。因此本程序自己截屏/录制必须换一条取帧路径，按优先级实测：

| 路径 | 做法 | 状态 |
| --- | --- | --- |
| P2 | `PrintWindow(PW_RENDERFULLCONTENT)` 直接向自己的窗口要一帧（不经过屏幕） | 首选；**能否可用取决于显卡/驱动/Windows 版本，必须在本机实测** |
| P3 | 临时解除保护 → 屏幕抓取 → 立刻恢复 | 保底：截图可用；录制期间会周期性暴露，故作为降级 |
| P4 | `GraphicsCaptureItem.CreateFromVisual`（视觉级捕获，可能不受窗口保护影响） | 本版只做可用性探测，未启用（真正取帧还需要一层 D3D11 回读） |

**怎么得到你这台机器的结论**：设置 → 安全 → **运行反截屏自检**（需要正在投屏）。它会逐条打印 P1–P4 的结果与最终结论，并写进日志。

**降级策略**（设置 → 安全，默认第一项）：
- `录制期间暂停保护`：能录上，但录制期间防截屏保护暂时失效（界面会明确提示）。
- `保护优先`：保护开启时**拒绝录制**（截图仍然可用，靠瞬时解除保护完成）。

## 九、仍然存在的风险（做不到的部分，如实列出）

| 风险 | 说明 | 缓解建议 |
| --- | --- | --- |
| 物理视线 | 站你身后的人直接看屏幕 | 无软件解；用 Ctrl+Alt+H 紧急隐藏（会停止投屏并上锁） |
| 你的 Windows 会话已解锁且人离开 | 别人打开本程序即可看到投屏画面（库仍需密码） | 开启 Windows 自动锁屏；离开前按 **Ctrl+Alt+L** 上锁；或用 Ctrl+Alt+H |
| 管理员/内核级攻击者、内存取证 | 能从内存里抓已解密的帧与私钥 | 无解；不要在不受信任的电脑上使用 |
| 硬件采集卡 / 外接录制设备 | 直接采集 HDMI/显示输出 | 无解 |
| SSD 删除不等于擦除 | 删掉的条目可能被数据恢复工具找回 | 开启 **BitLocker** 全盘加密 |
| 系统级痕迹 | Windows 会记录 Wi-Fi Direct 活动、无线显示设备历史（含最近连接时间）、事件日志；文件系统层面还有 MFT/USN 记录 | 设置里可开启"启动时清空设备历史"；系统级日志无法由本程序彻底清除 |
| 崩溃转储 | 若系统生成 `%LocalAppData%\CrashDumps`，可能含已解密帧 | 库空闲自动上锁（默认 5 分钟）可减少窗口；必要时关闭转储 |
| 元数据推断 | 库目录里文件的数量与体积会泄露"录了多少、大概多长" | 设置配额与保留策略（30/90 天）限制累积 |
| 弱密码 | 离线爆破的下限由密码强度决定 | 创建账号时强制 ≥8 位字母+数字并拦截常见弱口令 |

## 十、建议你手动确认的系统设置（一次性，5 分钟）

1. **设置 → 系统 → 投影到此电脑**：选「始终询问」/「仅第一次」按需，并**勾选「需要 PIN 才能配对」**（与程序内的「要求 PIN」互为补充）。
2. **设置 → 游戏 → Xbox Game Bar**：关闭「使用控制器打开 Xbox Game Bar」与**后台录制**（或用本程序设置 → 安全 → 一键关闭）。
3. **设置 → 隐私和安全性 → 回忆和快照**（若你的电脑有）：**关闭**。
4. **设置 → 隐私和安全性 → 常规**：按需关闭"让应用使用广告 ID / 在设备上显示建议内容"（与本程序无关，但同属隐私面）。
5. **BitLocker**：对系统盘开启（防止设备丢失后被离线取证）。
6. **路由器**：WPA2/WPA3、关闭 WPS、开启 AP 隔离；**不要在公共 Wi-Fi 下投屏**。
7. **远程协助类软件**（AnyDesk/TeamViewer/向日葵等）：不用时退出，不要常驻；本程序的反截屏保护会让它们拍成黑屏，但退出更彻底。
8. 若你曾在旧版本里截过屏/录过像：打开本程序 → 设置 → 安全 → **导入旧明文文件**（导入后自动删除明文原件），并点「清理临时帧残留」。
