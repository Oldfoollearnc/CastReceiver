# 投屏Window 桌面版 · v1.1.4

> 开发者：**猪猪**　|　手机镜像接收端（Miracast / Wi-Fi Display）　|　**安装包自带运行环境，装完即用**
> v1.1 起：**截图与录像加密保存**（只能在程序内查看）、**多账号隔离**、**反截屏保护**、**投屏隐私加固**。详见 [安全与隐私评估](docs/安全与隐私评估.md)。

![应用图标](docs/icon.png)

把 Windows 电脑变成**手机镜像接收端**：手机和电脑连同一个 Wi-Fi，用手机自带的「无线投屏 / 投射屏幕」就能把手机画面镜像到电脑上。

> **产品范围**：本程序**只做手机镜像（Miracast / Wi-Fi Display 接收端）**。
> 早期版本内置的「App 投屏（DLNA，腾讯视频等 App 的投屏按钮）」与 VLC 播放内核已按需求整体移除：
> 界面少了一整块、启动更快、发布包从 **135MB 降到 29MB**。
> DLNA 相关代码只保留在命令行自检工具里做回归验证，产品本身不再加载。

## 一、安装与使用

**安装**：双击 `发布版\投屏Window-Setup-1.1.4.exe` → 下一步 → 完成（默认装到当前用户目录，**不需要管理员权限**）。
安装包**已内含 .NET 10 桌面运行时与 WPF**（自包含发布），装完即可直接使用，无需再装任何组件；
自带开始菜单/桌面快捷方式与卸载程序。安装包 55 MB，安装后约 197 MB。

也可以免安装直接用绿色版：`发布版\投屏Window\投屏Window.exe`（同样自带运行环境）。

**使用（2 步）**：

1. **运行**：双击桌面快捷方式或 `发布版\投屏Window\投屏Window.exe`（或同目录 `启动投屏.cmd`）。
   双击后约 **0.5 秒**就会弹出启动动画，主窗口随后接管——不会再出现"点了没反应"的空窗期。
   界面顶部若显示黄色「还差一步：点「一键准备」」，点它并在 UAC 弹窗同意一次（放行防火墙 + 允许被发现，只需一次）。
2. **镜像**：手机下拉快捷面板 →「无线投屏 / 投射屏幕」→ 在设备列表里选择本机名称。
   手机开始连接时电脑端会立刻显示"手机正在连接…"的动画。

> **重复双击**：程序已在运行时不会再弹「已在运行」对话框，而是直接把已有窗口唤到前台（约 0.5 秒）。

**悬浮控制条（窗口模式也常驻）**：画面下方一直有一条悬浮控制条——

```
[全屏] | [适应]  [−] 100% [+] [⟲]
```

- **全屏**：一键进入；进入后按钮变成「退出全屏」（也能按 Esc / F11）
- **画面适配**：一点循环 适应 → 铺满 → 拉伸 → 原始
- **缩放**：−/+ 各 10%，⟲ 复位到 100%
- 它是独立顶层窗口，所以能浮在画面之上；**窗口模式下跟随主窗口层级**（不会浮到别的程序上），最小化时一起隐藏
- **没有音量控制**：镜像的声音由系统输出，调本地播放器音量对它无效，所以直接不做

**沉浸全屏（真正的无边）**：点悬浮控制条的「全屏」（或 F11）进入。上一版上下各留了一条固定高度的空白带、左右还有 1px 描边——
根因是**行高仍在占位**（隐藏内容不等于隐藏行）加窗口根边框；现在把行高归零、边框去掉，并直接铺满**整个显示器（含任务栏）**，
屏幕上一条边都没有。鼠标移到屏幕底部会浮出一条**悬浮控制条**：

```
[🔊] ─────●──── 87   [铺满]  [−] 100% [+]   [退出全屏]
```

- 控制条是**独立顶层窗口 + 鼠标穿透不抢焦点**，因此能浮在视频上（视频用 HwndHost 承载，WPF 元素无法叠加，这是绕开空域限制的做法）；
- **音量** 0–100（直接控制 MediaPlayer 输出）+ 静音；
- **画面适配**一点即循环：适应 → 铺满 → 拉伸 → 原始（见下）；
- **缩放** −/+ 每次 10%（范围 50%–200%，以画面中心为基准），另有 ⟲ 一键复位到 100%；
  > 上一版「缩小点了就不能放大」是控制条的栅格列数写成 6 列、元素却用到第 8 列，导致「＋」与「退出全屏」叠在同一格被盖住点不到；现已改为流式布局，并用 UI 自动化实测：100% → 80% → 100% → 110% → 复位 100% 双向可用。
- 鼠标离开底部 2.6 秒自动淡出；Esc / F11 也能退出。

**画面适配方式（四选一，设置窗口里可选，"铺满"不再是你唯一的选择）**

| 方式 | 效果 | 会不会变形 / 裁切 |
| --- | --- | --- |
| **适应** | 完整显示画面，四周按需留黑 | 不变形、不裁切（默认） |
| **铺满** | 等比放大到填满，超出部分裁掉 | 不变形，但**会裁掉边缘**（就是你说的"局部放大"） |
| **拉伸** | 强行拉满整块区域 | 填满且不裁切，但**可能变形** |
| **原始** | 1:1 像素，不缩放 | 画面比区域大时裁切，小则居中留边 |
| **缩放** | 在上面任一方式之上再 ×50%–200% | 以中心为基准放大/缩小 |

设置窗口里同时有四个按钮（当前项高亮）+ 缩放滑杆，改完立即生效并记住。

**退出全屏会精确回到进入前的位置和大小**（实测：1120×720 @ (1160,336) → 全屏 3440×1440 @ (0,0) → 退出后仍是 1120×720 @ (1160,336)）。

**通讯状态浮层（画面右上角）**：投屏时右上角会显示一张小卡片，实时反映"有没有延迟、通讯是否健康"：

```
● 推送中 03:12 · 滞后 0.2s · 实时 0.99
  低延迟 1280×720@4Mbps · 音量 80 · 无停滞
```

- **滞后** = 播放过程中"真实时间 − 画面推进"的累计秒数：稳定在 0.x 秒说明画面紧跟手机；持续上涨说明管道在落后，
  也就是你感觉到的"延迟在变大"（Miracast 无法给出绝对毫秒级延迟，这是接收端能得到的最接近的实时指标）；
- **实时比** = 画面位置推进速度 ÷ 真实时间。≈1.00 表示完全跟得上；持续 <0.9 说明管道在落后；
- **停滞** 统计画面卡住的次数与累计时长（例如 `停滞 2 次/3s`）；
- 圆点颜色：绿=健康，黄=缓冲中/刚停滞过，红=已无画面；
- 它同样用独立顶层小窗口实现，所以能浮在画面上，且**鼠标穿透**、不抢焦点；可在设置里关闭。
- 备注：Miracast 是直播流，个别驱动不回读播放位置；这种情况下浮层自动退化为只显示播放状态，不会误报停滞。
**连接中有动画**：手机点投屏后，电脑端会显示「手机正在连接」的转圈动画并**实时显示已等待秒数**。
判据来自接收端的握手状态（`ConnectionPending`）。

**只在出问题时才出现按钮**：正常状态下侧栏只有「状态 + 接收端开关」，不会堆按钮和说明文字；
只有在真的需要时才浮出对应动作——

| 情况 | 出现的按钮 |
| --- | --- |
| 网络未放行 | 一键准备 |
| 接收端意外停止 / 手机连接超过 20 秒 / 上次连接失败 | 重新开启接收端 / 重启接收端 |
| 镜像中画面推进跟不上（滞后 > 2.5s 或实时比 < 0.92） | 延迟优先 |

**首次启动的使用引导**：第一次运行会播放 4 步动画（连同一个 Wi-Fi → 手机下拉面板点无线投屏 → 选本机 → 悬浮条怎么用），
每步 4 秒自动前进、可跳过；之后可在「设置 → 使用引导」重看。
## 加密库与隐私（v1.1 新增）

### 一句话

**投屏、截屏、录制都不用输密码；要看截图和录像，必须输密码。** 密码不是软件里的一道开关，而是加密学意义上的钥匙 —— 把整个库拷到别的电脑也解不开。

### 怎么用

1. 第一次点「截屏」「录制」或「我的库」时，会让你**创建一个账号**（账号名 + 密码，密码至少 8 位含字母数字，弱口令会被拦掉）。
2. 之后投屏时点截屏/录制，内容直接加密存进「我的库」——**磁盘上不会出现任何明文文件**。
3. 看内容：点「我的库」→ 输密码 → 在窗口里看图片、播放录像（支持播放/暂停、逐帧、0.5–2× 变速、全屏）。
4. 关闭库窗口、按 `Ctrl+Alt+L`、或空闲超过设定分钟数，**立即上锁**（内存里的密钥清零）。

```
┌──────────────────────────────────────────────────────────────────────┐
│ 我的库  [账号名]  已解锁          [导入旧文件] [清空库] [锁定] [✕]     │
├───────────────────────┬──────────────────────────────────────────────┤
│ ▣ 录像 00:12          │                                              │
│ ▣ 截图 1440×900       │            解密后的画面（只在内存里）          │
│ ▣ 录像 00:03 未完成   │                                              │
│                       │  [▶] ──────●──────  37/120  1.0×  [⛶]        │
│                       ├──────────────────────────────────────────────┤
│                       │ 类型/开始时间/时长/帧数/大小  [标题] [保存] [删除]│
├───────────────────────┴──────────────────────────────────────────────┤
│ 共 12 条（截图 5 / 录像 7）占用 184.2 MB   空格 播放/暂停 · ←→ 逐帧 · Del 删除│
└──────────────────────────────────────────────────────────────────────┘
```

### 账号与「设备归属」

- **一个账号一套密钥、一个独立的库**：账号 A 看不到账号 B 的内容。
- **投屏设备决定内容归属**：第一次遇到某台手机时问你一次「这台设备归入哪个账号」，之后它投屏时截的屏/录的像自动进对应账号的库（侧栏「内容归属」一直显示当前归属）。
- 设备身份用的是「设备名 + 无线地址」的指纹，**只用来判断归属，不作为密码**（改名或伪造地址都拿不到内容）。
- 账号名在磁盘上用 DPAPI 保护、设备地址用 HMAC 存储，`accounts.json` 里没有明文账号名与明文 MAC。

### 反截屏保护

开启后（默认开），**其他程序**截取本程序窗口时只会得到黑屏 —— 包括会议共享、远程协助、录屏软件、系统截图工具。

本程序自己当然还要能截屏/录制，所以「怎么拿到画面」是实测决定的：

| 路径 | 说明 |
| --- | --- |
| `PrintWindow(PW_RENDERFULLCONTENT)` 直接向自己的窗口要一帧 | 首选：保护全程不降级 |
| 瞬时解除保护 + 屏幕抓取 | 保底：截图可用；录制会周期性暴露 → 按设置降级 |
| `GraphicsCapture` 视觉级捕获 | 本版仅探测可用性，未启用 |

设置 → 安全 → **运行反截屏自检**（需正在投屏）会给出你这台机器的实测结论；降级策略可选「录制期间暂停保护」或「保护优先（禁止录制）」。

### 投屏侧的隐私加固

| 项 | 默认 | 说明 |
| --- | --- | --- |
| 隐私日志模式 | **开** | 投屏的连接/断开事件不写日志文件（避免"什么时候投的屏"被留痕） |
| 界面显示手机名称 | **关** | 界面/托盘只显示「已连接」，不暴露你在用什么设备 |
| 允许其他设备抢占投屏 | **关** | 别人的手机不能顶掉你正在进行的投屏 |
| 启动时清空设备历史 | 关 | 打开后会清掉系统记录的"上次连接过的设备" |
| 配对方式 | 本机确认 | 可改为「要求 PIN」：配对时本机显示 PIN，需要在手机上输入 |
| 发送端反向控制键鼠 | **始终关闭** | 协议允许发送端请求键盘/手柄输入转发，本程序连接时显式拒绝 |

### 隐私体检（设置 → 安全）

逐项检查：Xbox Game Bar 后台录制、Windows 回忆（Recall）、旧版本的明文文件、`%TEMP%` 明文帧残留、云盘同步范围、日志隐私、反截屏、设备历史、库是否已上锁。能一键修的只有当前用户（HKCU）项。

### 旧版本留下的明文文件怎么办

设置 → 安全 → **导入旧明文文件**：把 `视频\投屏Window`、`图片\投屏Window` 里的旧 PNG/MP4 导入加密库（MP4 会按帧重建为库内可播放的录像），导入成功后删除明文原件；另有「删除旧明文文件」「清理临时帧残留」两个按钮。

完整的风险分析、做不到的事、建议的系统设置清单见 **[docs/安全与隐私评估.md](docs/安全与隐私评估.md)**。

## 三、启动与响应性（都做了实测）

| 项目 | 结果 |
| --- | --- |
| 双击 → 看到启动动画 | **约 0.5 秒**（原生 Win32 窗口绘制，绕开 WPF 首次初始化；实测原生窗口在 Main 入口后 326ms 显示） |
| 双击 → 主界面完全就绪 | 约 2.1 秒（含接收端开启） |
| 已在运行时再次双击 | 唤起已有窗口，第二个实例约 470ms 自行退出，始终只有 1 个实例 |
| 空转 CPU | **单核 2.1%**（整机 0.13%，16 核实测） |
| 发布包 | 29MB（纯镜像，无 VLC） |
| 界面压力测试 | 设置/开关/延迟切换/全屏/重启接收端 真实点击，6/6 采样响应、0 停顿告警、0 异常、优雅退出 |

启动耗时的实测分解（相对 Main 入口）：闪屏 326ms → 主窗口对象 1384ms → 主窗口渲染完成 2142ms。
其中「解析 XAML 约 700ms + 显示第一个 WPF 窗口约 950ms」是 WPF 的固定开销，因此启动动画改用原生窗口实现。

应用内置停顿自检：UI 定时器发现两次 tick 间隔超过 1.5 秒会写一条 `界面线程停顿 Xms` 到日志，便于日后定位。

## 四、偶发投屏不上？已经能自愈

实测过的现象：**偶发投屏不上，重启一下桌面端就好了**。根因是 Wi-Fi Direct 会话进入异常状态
（监听状态丢失，或手机停在"正在连接"而本机收不到连接），旧版本只能靠重启程序复位。现在加了看门狗：

| 检测 | 动作 |
| --- | --- |
| 监听状态异常（不再是 Listening） | 立即重建接收会话（销毁 → 重新启动） |
| 手机卡在"正在连接"超过 25 秒 | 判定为卡死，重建会话 |
| 连续两次以上恢复失败 | 升级为结束卡死的无线显示后台进程 `CastSrv` 后再试 |
| 连续 5 次仍失败 | 停止重试并在动态里提示，可手动点「重启接收端」 |

即：**大多数情况下你什么都不用做，界面会自己显示"接收端无响应，正在自动恢复…"然后恢复**。

## 五、延迟优化（尽量做到最低）

镜像链路的延迟 = **手机编码 + 无线传输 + 本机解码 + 显示**。本程序在接收端能做的都做了：

| 措施 | 说明 |
| --- | --- |
| **向手机申请低延迟流参数** | `MiracastReceiverStreamControl.SuggestVideoStreamSettings`：延迟优先时申请 **1280×720 @4Mbps**（分辨率/码率越低，编码、传输、解码三段都更快）。点「延迟优先/画质优先」可**热切换**，无需重连 |
| **实时播放模式** | `MediaPlayer.RealTimePlayback = true`（Miracast 必需，否则会一直缓冲甚至花屏） |
| **关闭帧服务器** | `IsVideoFrameServerEnabled = false`，避免多一次拷贝 |
| **渲染表面 = 视频真实分辨率** | `SetSurfaceSize` 跟随 `NaturalVideoSizeChanged`，省掉一次缩放 |
| **零拷贝 GPU 呈现** | `MediaPlayer.GetSurface` → `Windows.UI.Composition` 的 `SurfaceBrush` → `DesktopWindowTarget`，全程 GPU、无 CPU 回读 |
| **可选静音** | 设置里勾选「镜像静音」：省掉音频同步缓冲，进一步降延迟 |

> 官方给出的 Miracast 端到端延迟量级约 250ms 起，其中大部分由**发送端编码与无线传输**决定，接收端只能压掉解码与呈现这一段。若仍觉得不够跟手，优先用「延迟优先」+「镜像静音」，并把手机与电脑放在同一 5GHz 频段、避开移动热点。

## 六、自检（命令行工具，开发/回归用）

## 七、常见问题

**Q1：手机搜不到电脑？** ① 是否点过「一键准备」并同意 UAC；② 网络位置是否为「专用」；③ 是否同一个 Wi-Fi；④ 路由器是否开了 AP 隔离；⑤ 是否开着移动热点（会占用 Wi-Fi Direct，界面会橙字提示，可点「关闭移动热点」自动释放）。

**Q2：手机点投屏后一直连不上 / 电脑端没反应？** 先等 25 秒——看门狗会自动重建会话（界面上会显示"正在自动恢复"）。若仍不行，点「重启接收端」（会先清理卡住的 `CastSrv`）；再不行就关闭再打开一次手机 Wi-Fi（复位 Wi-Fi Direct 协议栈）。

**Q3：画面有黑边？** 竖屏手机镜像到宽屏必然留黑。点「铺满画面」裁切填满，或直接「全屏」（会自动铺满）。

**Q4：觉得不够跟手？** 见第四节：用「延迟优先」+「镜像静音」，并确认手机与电脑在同一 5GHz 频段。
